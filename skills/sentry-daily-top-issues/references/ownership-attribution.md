# Sentry 错误归因 Reference

仅在需要给 Issue 标注 `Web 前端`、`后端`、`客户端` 或 `待核实` 时读取本 Reference。归因是排查方向，不是已确认根因；始终同时输出置信度和可验证证据。

## 证据优先级

按以下顺序组合证据，不得仅凭项目名称或错误标题归因：

1. Sentry 事件的 `platform`、SDK 类型和运行时信息。
2. 代表性堆栈的文件类型、函数和首方代码位置。
3. 页面路由、请求 URL、HTTP 状态、超时和响应上下文。
4. `release`、环境、浏览器/设备信息及同一 fingerprint 的跨端分布。

## 归因规则

| 归因        | 充分证据                                              | 输出示例                                  |
| ----------- | ----------------------------------------------------- | ----------------------------------------- |
| Web 前端    | 浏览器 JS 异常、页面路由、DOM/组件、Fetch/XHR 调用栈  | `Web 前端（初步判断）`                    |
| 后端        | 服务端堆栈、接口 5xx、网关错误或服务端超时证据        | `后端（初步判断）`                        |
| 客户端      | Android/iOS/Unity 等原生堆栈、原生 SDK 或设备崩溃信息 | `客户端（有原生证据）`                    |
| 跨端/不确定 | 浏览器仅表现为请求失败，或证据同时指向多个层          | `Web 前端表现，后端待核实` / `归因待核实` |

`maidocha-mobile` 等名称不等于原生客户端；如果 Sentry 事件来自浏览器/H5，仍归为 Web 前端。没有原生 SDK 或原生堆栈证据时，禁止标注“客户端”。

## 输出约束

- `layer` 只能取 `Web 前端`、`后端`、`客户端`、`归因待核实` 或跨端组合描述。
- `confidence` 取 `高`、`中`、`低`，并列出触发判断的最小证据。
- 证据不足时不得写成确定根因；建议明确下一步核对项（接口响应、服务端日志、客户端版本或复现环境）。
- 不输出完整堆栈、IP、用户标识、原始敏感标签或凭据。
