# Sentry 错误归因 Reference

仅在需要补充归属或排查方向时读取。先判断运行环境、观测主体和异常实际发生层，
再判断 `layer`（代码/执行层）与 `phenomenon`（现象/环境因素），最后给分类可信度。
归因不是已确认根因；Android、iOS、WebView、App release 和业务分组只是上下文，不能
单独决定 `layer`。

## 固定输出

每个 Issue 输出以下字段：

```text
layer:
phenomenon:
confidence:
evidence:
next_check:
```

`layer` 只能取：

- `Web 前端`
- `后端`
- `客户端`
- `跨端待核实`

`phenomenon` 可取：

- `应用代码异常`
- `资源加载异常`
- `网络疑似异常`
- `运行环境/兼容性`
- `宿主集成异常`
- `后端响应异常`
- `未知`

`phenomenon` 不是根因。`网络疑似异常`表示请求或连接表现符合网络问题特征，不表示
已经证明运营商、CDN、网关或服务端故障。允许记录一个主现象和一个次现象，但不得
把多个信号压缩成未经证实的根因。

## 决策流

### 1. 前置分类条件

先分别记录以下信息，避免把“谁观察到异常”误当成“谁造成异常”：

- `runtime`：`browser`、`WebView`、`native`、`server` 或 `unknown`。
- `observer`：`Web JS`、`native`、`server`、`gateway` 或 `unknown`。
- `direct_evidence`：同一异常是否有 Web JS 堆栈、原生堆栈、服务端日志/堆栈或可靠
  trace 关联。

前置证据优先级固定为：直接异常堆栈，其次可关联的服务端或原生日志，再次明确的
响应体/HTTP 状态，最后才是平台、设备、release、域名等上下文。不同来源的证据不能
仅凭数量相加，必须判断是否属于同一异常链路。

### 2. 判定执行层

按以下顺序选择唯一 `layer`：

1. 有服务端运行时堆栈、服务端日志、网关日志或可靠 trace 明确关联服务端异常
   → `后端`。
2. 有 Android/iOS/Unity 原生堆栈、原生 SDK 异常、宿主日志或明确宿主网络配置证据
   → `客户端`。
3. 有浏览器或 WebView 内的 H5、Vue/React、DOM、Canvas、WebGL、Fetch/XHR 等
   Web JS 业务堆栈 → `Web 前端`。
4. 只有请求失败、超时、HTTP 状态或跨层信号，无法确认异常实际发生层
   → `跨端待核实`。

WebView 只改变 `runtime`，不改变 Web JS 的 `layer`。页面 JavaScript 报 JSBridge
对象缺失、注入时序错误或宿主 API 不可用时，若没有原生直接证据，仍判
`Web 前端`，现象判为 `宿主集成异常`。只有原生直接证据才判 `客户端`。

HTTP 4xx/5xx 首先只能支持 `后端响应异常` 这一现象，不能单独决定 `layer: 后端`。
`Failed to fetch`、客户端超时和 `status_code: 0` 同样不能单独决定后端或客户端。

### 3. 判定现象

按证据选择一个主现象；存在独立且相关的第二条证据时，可追加一个次现象：

- TypeError、空对象、组件、渲染循环、业务函数异常 → `应用代码异常`。
- 静态 JS/JSON/图片/音频/资源获取失败 → `资源加载异常`。
- WebGL、浏览器能力、设备差异、旧版 WebView 行为 → `运行环境/兼容性`。
- JSBridge、原生注入对象或宿主 API 缺失 → `宿主集成异常`。
- 明确收到 4xx/5xx 或响应体支持服务端拒绝/失败 → `后端响应异常`。
- 至少两个独立网络信号同时出现 → `网络疑似异常`：
- 多个不同资源或请求在相近时间失败。
- 出现超时、连接中断、`status_code: 0`、`ERR_NETWORK` 或同类网络错误。
- 同一资源在其他请求中成功，或同一 Issue 跨用户/跨网络集中出现失败。
- 运行时记录离线、网络切换、弱网或连接重置。

单独的 `Failed to fetch`、请求失败或 `status_code: 0` 只说明观测方未取得正常响应，
可以触发网络核查，但不能单独证明网络抖动、客户端故障或后端故障。

### 4. 分级可信度

`confidence` 只评价当前 `layer + phenomenon` 分类，不评价根因是否已经确认：

- `高`：分类有直接堆栈、原生日志或服务端日志，并有独立上下文印证。
- `中`：有多个相关信号，但缺少直接发生层证据或 trace 关联。
- `低`：只有标题、单个请求失败、设备信息或无法关联的环境信息。

如果内部需要更细粒度，分别记录 `layer_confidence` 和 `phenomenon_confidence`；
对外仍兼容输出单个 `confidence`。无论可信度高低，`root_cause` 都默认为“未确认”。

## 归属细则

- `platform: javascript` 只有与浏览器/H5/页面路由或 WebView JS 堆栈结合时，才形成 `Web 前端` 证据。
- H5 在 Android/iOS WebView 中运行，代码归属仍是 `Web 前端`；设备/WebView 只补充
  `运行环境/兼容性`。
- `maidocha-mobile`、release 名称、页面项目名和 URL 域名只提供上下文，不单独决定归属。
- 浏览器出现请求失败时，保留 `Web 前端` 或在责任层无法确认时输出
  `跨端待核实`，并将网络/后端放入 `phenomenon` 或 `next_check`。
- 只有原生堆栈、原生 SDK、宿主日志或明确宿主配置证据时才输出 `客户端`。
- 前端代码异常与资源/网络现象同时存在时，保留 Web 前端层，输出主现象和次现象，
  并在 `next_check` 写明另一条链路。

证据列只写 2–4 条最小可验证事实，并区分“异常发生证据”和“环境上下文”。
`next_check` 指向具体核对项，例如接口响应/网关日志、资源发布与 CDN、浏览器/设备
矩阵、宿主注入或代码生命周期；证据不足时使用“待核实”，不写确定根因。

不输出完整堆栈、IP、用户标识、原始敏感标签或凭据。
