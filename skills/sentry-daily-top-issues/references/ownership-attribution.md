# Sentry 错误归因 Reference

仅在需要补充归属或排查方向时读取。先判断 `layer`（代码/执行层），再判断 `phenomenon`（现象/环境因素），最后给 `confidence`。归因不是已确认根因。

## 固定输出

每个 Issue 输出以下字段：

```text
layer:
phenomenon:
confidence:
evidence:
next_check:
```

`layer` 只能取：

- `Web 前端`
- `后端`
- `客户端`
- `跨端待核实`

`phenomenon` 可取：

- `应用代码异常`
- `资源加载异常`
- `网络疑似异常`
- `运行环境/兼容性`
- `宿主集成异常`
- `后端响应异常`
- `未知`

`phenomenon` 不是根因。`网络疑似异常`表示请求或连接表现符合网络问题特征，不表示已经证明运营商、CDN、网关或服务端故障。

## 决策流

按顺序执行，命中后仍可补充第二层现象：

1. 读取 `platform`、SDK、运行时、代表性堆栈、路由、请求和环境信息。
2. 先判执行层：
   - 浏览器 JS、H5 页面、DOM/组件、Fetch/XHR 调用栈 → `Web 前端`。
   - 服务端运行时堆栈、网关/服务端日志、可关联的接口 5xx 或服务端超时 → `后端`。
   - Android/iOS/Unity 原生堆栈、原生 SDK 崩溃或 native exception → `客户端`。
   - 证据同时指向多个层，或只有跨层请求失败表现 → `跨端待核实`。
3. 再判现象：
   - `TypeError`、空对象、组件、渲染循环、业务函数异常 → `应用代码异常`。
   - 静态 JS/JSON/图片/音频/资源加载失败 → `资源加载异常`。
   - WebGL、浏览器能力、设备差异、旧版 WebView 行为 → `运行环境/兼容性`。
   - JSBridge、原生注入对象或宿主 API 缺失 → `宿主集成异常`。
   - 接口明确返回 4xx/5xx，或服务端响应体/错误码直接支持服务端异常 → `后端响应异常`。
4. 最后判断网络信号。满足以下至少两项，才标记 `网络疑似异常`：
   - 多个不同资源或请求在相近时间失败。
   - 出现超时、连接中断、`status_code: 0`、`ERR_NETWORK` 或同类网络错误。
   - 同一资源在其他请求中成功，或同一 Issue 跨用户/跨网络集中出现失败。
   - 运行时记录离线、网络切换、弱网或连接重置。

单独的 `Failed to fetch`、请求失败或 `status_code: 0` 只说明浏览器未取得正常响应。它可以触发网络核查，不能单独证明网络抖动，也不能直接归因为后端。

## 归属细则

- `platform: javascript` 只有与浏览器/H5/页面路由或 WebView JS 堆栈结合时，才形成 `Web 前端` 证据。
- H5 在 Android/iOS WebView 中运行，代码归属仍是 `Web 前端`；设备/WebView 只补充 `运行环境/兼容性`。
- `maidocha-mobile`、release 名称、页面项目名和 URL 域名只提供上下文，不单独决定归属。
- 浏览器出现请求失败时，优先输出 `Web 前端` 或 `跨端待核实`，并将网络/后端放入 `phenomenon` 或 `next_check`。
- 只有明确原生堆栈或原生 SDK 证据时才输出 `客户端`。
- 前端代码异常与资源/网络现象同时存在时，`layer` 保留 `Web 前端`，`phenomenon` 选择主要现象，并在 `next_check` 写明另一条链路。

## 置信度

- `高`：存在直接的首方堆栈、运行时类型或明确响应证据，且至少有一项上下文相互印证。
- `中`：有两个独立上下文信号，但缺少直接根因证据。
- `低`：只有通用错误标题、单一请求失败或无法关联的环境信息。

证据列只写 2–4 条最小可验证事实。`next_check` 指向具体核对项，例如接口响应/网关日志、资源发布与 CDN、浏览器/设备矩阵、宿主注入或代码生命周期；证据不足时使用“待核实”，不写确定根因。

不输出完整堆栈、IP、用户标识、原始敏感标签或凭据。
